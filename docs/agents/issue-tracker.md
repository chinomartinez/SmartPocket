# Issue tracker: Local Markdown

Los issues y specs de este repo viven como archivos markdown bajo `docs/planning/<feature-slug>/`.

## Convenciones

- Una feature por directorio: `docs/planning/<feature-slug>/`
- La spec es `docs/planning/<feature-slug>/spec.md`
- Los issues de implementación van uno por archivo en `docs/planning/<feature-slug>/issues/<NN>-<slug>.md`, numerados desde `01`. Nunca un archivo combinado de tickets.
- Cada issue lleva una línea `Type:` (categoría) y una línea `Status:` (estado de triage) cerca del inicio. Ver `triage-labels.md`.
- Los comentarios y el historial se agregan al final del archivo bajo el heading `## Comments`.
- Todo comentario o issue generado durante triage empieza con la línea:
  `> *This was generated by AI during triage.*`

## Cuando una skill dice "publicá en el issue tracker"

Creá un archivo nuevo bajo `docs/planning/<feature-slug>/`, creando el directorio si hace falta.

## Cuando una skill dice "traé el ticket relevante"

Leé el archivo en el path referenciado. Normalmente el usuario pasa el path o el número directamente.

## Listar lo que necesita atención

Recorré `docs/planning/*/issues/` y agrupá los archivos abiertos en tres buckets, del más viejo al más nuevo:

1. **Sin `Status:`**: nunca triados.
2. **`Status: needs-triage`**: evaluación en curso.
3. **`Status: needs-info` con actividad del reporter**: requieren re-evaluación.

## Conocimiento de descartes

Los pedidos rechazados se registran en `.out-of-scope/` en la raíz del repo, un archivo por tema.
Antes de recomendar `wontfix` por rechazo, leé `.out-of-scope/*.md` y citá el archivo que corresponda.

## Operaciones de wayfinding

Usadas por `/wayfinder`. El **mapa** es un archivo con un **ticket hijo** por archivo.

- **Mapa**: `docs/planning/<effort>/map.md` con el cuerpo de Notas / Decisiones tomadas / Niebla.
- **Ticket hijo**: `docs/planning/<effort>/issues/NN-<slug>.md`, numerado desde `01`, con la pregunta en el cuerpo. Una línea `Type:` registra el tipo (`research`/`prototype`/`grilling`/`task`); una línea `Status:` registra `claimed`/`resolved`.
- **Bloqueo**: una línea `Blocked by: NN, NN` cerca del inicio. Un ticket está desbloqueado cuando todos los archivos que lista están `resolved`.
- **Frontera**: escaneá `docs/planning/<effort>/issues/` buscando archivos abiertos, desbloqueados y sin reclamar. Gana el de menor número.
- **Reclamar**: poné `Status: claimed` y guardá antes de cualquier trabajo.
- **Resolver**: agregá la respuesta bajo un heading `## Answer`, poné `Status: resolved`, y sumá el puntero de contexto a las Decisiones tomadas en `map.md`.
